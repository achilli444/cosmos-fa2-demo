### Mission impact (for a C2 operator)

- **A1 config-overlay RCE.** Any authenticated user may write under `targets_modified/`; target config is ERB-evaluated on load. Impact: an operator-level account (not admin) gets arbitrary Ruby on the cmd/tlm host — command authority over every target in scope, silently, with the malicious config persisting across restarts.
- **A2 `pypi_url` command injection.** The `pypi_url` admin setting is spliced into a backtick shell command at plugin install. Impact: whoever can set one string owns the API container; plugin install is a routine ops action, so the trigger looks like normal maintenance.
- **A3 unauthenticated global logout.** `PUT /openc3-api/users/logout/:user` calls `AuthModel.logout` (`Store.del(SESSIONS_KEY)`) with no `authorization()` check. Impact: one unauthenticated request from anywhere with network reach terminates every operator session at once — denial of command-and-control mid-contact, repeatable on a loop.
- **A4 Script Runner suite injection.** `suite`/`group`/`method` from the client are interpolated into Ruby source and executed. Impact: bypasses the Script Runner approval boundary — code runs that no reviewer approved, from an account that is only allowed to run *approved* procedures.
- **A5 stored XSS via BUTTON.** Button text is `eval()`'d in every operator's browser that opens the screen. Impact: one screen edit turns into command execution in other operators' sessions (their token, their permissions).
- **A6 heap OOB read.** Integer overflow in bit-offset/size checks in the native accessor. Impact: crafted telemetry/packet definitions read out of bounds — crash (loss of telemetry processing) or memory disclosure in the decom/API process.
- **A7 `public_send` bypass.** The JSON-RPC denylist blocks `send`/`__send__` but not `public_send`. Impact: authenticated caller reaches API-object methods the interface never intended to expose; scope of harm depends on reachable methods (advisory: medium).
- **A8 swallowed AuthError.** `rescue Exception` after `authorize(permission: 'admin')` means a non-admin's call proceeds past the check. Impact: authorization failure is logged as a generic error and the write path continues — an audit gap rather than a direct C2 takeover.

### Mission impact (written for a C2 operator), one paragraph per open finding

**F1 — Native bounds-check overflow from a crafted variable-length telemetry packet** (`sfind-d384fe99367b424fbccdda28b7f6be4f`, high; MATCH A6 — GHSA-g7jg-9chv-jq9j / CVE-2026-92167). `check_bounds_and_buffer_size` computes `(bit_offset + bit_size - 1) / 8` in 32-bit signed arithmetic; a `VARIABLE_BIT_SIZE` length field inside the packet drives `bit_offset` toward `INT_MAX`, the sum wraps negative and the only guard passes. The reader then dereferences roughly ±256 MiB outside the Ruby string, and the bitfield path `memcpy`s with a negative length. One 24-byte packet that identifies as the shipped `INST VARIABLE_ARRAYS` definition — delivered over the target's TCP/UDP link or a router — crashes the decom microservice (loss of telemetry processing for every operator on that target) or reads heap memory of the process. Reachability: interface read → `handle_packet` → `Packet#buffer=` → `recalculate_bit_offsets` → native `binary_accessor_read`. Recommendation (from the scan): do the bounds math in 64-bit and reject negative bounds; validate `num_bytes > 0` before every `memcpy`; cap `VARIABLE_BIT_SIZE` lengths against the real buffer length on the Ruby side.

**F2 — `public_send` missing from the JSON-RPC denylist** (`sfind-579942799fc3496f985b17ef2cb824ca`, high; MATCH A7 — GHSA-q2gf-g584-w94p / CVE-2026-92166). When a `JsonDRb` instance runs without a `method_whitelist`, the only guard is `DANGEROUS_METHODS = ['__send__','send','instance_eval','instance_exec']`. A request `{"method":"public_send","params":["send","eval","<ruby>"]}` becomes `public_send(:send, :eval, code)` and reaches private `Kernel#eval` — arbitrary Ruby in the serving process. The shipped cmd-tlm-api sets `Api::WHITELIST`, so no default deployment is exploitable; the exposure is any plugin microservice or tool that follows the documented `start_service(host, port, object)` example without a whitelist. Rated high by profile rule (dispatch outside the intended API surface); exploitability difficult. Recommendation (from the scan): make the whitelist mandatory (raise when nil), drop the denylist fallback, or at minimum add `public_send`, `method`, `public_method`, `instance_variable_get/set`, `define_singleton_method`.

**F3 — `update_news` swallows the authorization failure** (`sfind-17c453e1b23c49158b53a91fdb8fbdeb`, high by profile rule, content impact low; MATCH A8 — GHSA-jmg5-qfmh-4jh3 / CVE-2026-92168). `authorize(permission: 'admin')` sits inside a method-level `rescue Exception`; an unauthenticated JSON-RPC call raises `AuthError`, the rescue writes `NewsModel.news_error(...)` to the global `openc3_news` key and returns success. Anyone who can reach `/openc3-api/api` with no token overwrites the news feed every operator sees with a fixed "News Error" entry. No attacker-controlled text and no C2 effect — the operational significance is the pattern: an authorization failure that is logged and then proceeds to a write. Recommendation (from the scan): authorize before the rescued region and wrap only the Faraday fetch; never `rescue Exception` around `authorize`.

**F4 — Command identity spoofing through ID_PARAMETER overwrite** (`sfind-0b6be098f88c4adf9824f9011d08100c`, medium; NEW / unverified). `build_cmd`/`set_parameters` write every caller-supplied parameter into the buffer including the packet's opcode/ID items; `cmd_no_range_check` disables the only check that would reject a changed ID while requiring the same `cmd` permission as `cmd`. An operator cleared for benign command X sets X's opcode to restricted/hazardous command Y's ID: COSMOS authorizes, hazard-checks, approval-gates, logs and decoms it as X, and the spacecraft executes Y. Defeats per-command RBAC, two-person critical commanding and `disable_cmd` in Enterprise; in Core the audit trail is what is falsified. Recommendation (from the scan): reject writes to `id_value` items that differ from the packet's ID regardless of `range_check`, or re-identify the built buffer and fail if it does not resolve to the requested packet.

**F5 — `get_packets` reads any Redis stream the caller names** (`sfind-c5f7771f3ae847039545348a20840e5b`, medium; NEW / unverified). `subscribe_packets` authorizes each target/packet and builds topic names; `get_packets` then trusts the caller's `id` string, authorizes only scope-wide `tlm`, and `XREAD`s whatever streams are embedded in it — another scope's `DECOM` stream, a restricted target, or the `DECOMCMD` command history normally behind `cmd_info`. A viewer-level token in one scope reads decommutated telemetry and command history it was never granted. Requires an `authorize` that enforces per-target/per-scope permissions (Enterprise). Recommendation (from the scan): parse each topic with an anchored regex bound to the caller's scope and re-authorize per target/packet; reject `DECOMCMD`/`COMMAND`/`TELEMETRY` streams.

**F6 — `connect_interface` reconfigures and persists the link with caller-supplied constructor parameters** (`sfind-53daf33c8cb84ae2be0964a8c1155875`, medium; NEW / unverified). The API method checks only `system_set`; the interface microservice JSON-parses the parameters, runs `@interface.class.new(*params)` and writes them into the persisted `InterfaceModel`. A connect/disconnect-level user re-points a `TcpipClientInterface`/`HttpClientInterface`/`MqttInterface` to an attacker host — every operator's commands and the telemetry the ground system trusts now transit that host (command interception/spoofing, SSRF from the operator container) — or redirects a `FileInterface`'s folders to arbitrary operator-container paths; the change survives restarts. Enterprise escalation only. Recommendation (from the scan): require admin when `interface_params` is non-empty, check command authority for mapped targets, allowlist runtime-changeable parameters, and do not persist runtime overrides.

**F7 — `connect_router` — same weakness on the router path** (`sfind-a2d0bb430b92453890ded6ed71404580`, medium; NEW / unverified). Identical pattern to F6 for routers, which bridge external clients to target command/telemetry streams: a `system_set` user rebuilds and persists a router pointed at an attacker-chosen host/port or listening port, forwarding telemetry outward and exposing a command-relay endpoint into mapped targets. Recommendation (from the scan): as F6, and check command authority for `router_cmd`/`router_protocol_cmd`.

**F8 — `send_raw` skips `cmd_raw` authorization on interfaces with no mapped command targets** (`sfind-604fdb35de40426789813818c494e665`, medium; NEW / unverified). Ruby `send_raw` authorizes `cmd_raw` once per entry in `cmd_target_names`; if the interface is telemetry-only or its targets were unmapped, the loop never runs and raw bytes go to `InterfaceTopic.write_raw` after only a `system` (read) check. A view-level Enterprise role writes arbitrary bytes onto the device link. The Python API does a single interface-level `cmd_raw` check, so the Ruby side diverges from intended policy. Recommendation (from the scan): authorize `cmd_raw` unconditionally at interface level before writing.

**F9 — Two-person approval under `critical_commanding = ALL` keyed to a client-asserted flag** (`sfind-f97a9da07757455caa9bfc73a892837b`, medium; NEW / unverified). In `ALL` mode the interface microservice holds a non-hazardous command for second-person approval only when `manual` is true; `manual` comes from the client's `Manual` HTTP header or JSON keyword param, defaults to false, and is forwarded unchanged. A `cmd`-permitted user calls the API directly without the header and the command goes to the target with no approval record — the two-person control exists only for operators who use the UI. Enterprise feature; hazardous/restricted commands still require approval. Recommendation (from the scan): require approval for every non-released command in `ALL` mode, or derive manual/automated provenance server-side (e.g. from a script-runner-issued identity) and ignore the request flag.

**F10 — Regex injection / ReDoS in `get_overall_limits_state`** (`sfind-717ce5dfd2e04783b37edea5650cad5a`, medium; NEW / unverified). `ignored_items` is interpolated unescaped into `/^#{item}/` and evaluated against every out-of-limits item name with no `Regexp.timeout`. A `tlm`-level token sends a catastrophic-backtracking pattern (with a backreference to defeat Ruby 3.2+ memoization); a handful of concurrent requests pin the cmd-tlm-api Puma workers — the limits monitor and every other API consumer stall while a pass is in progress. Precondition (at least one item out of limits) is normal in live ops. Recommendation (from the scan): `Regexp.escape` or a plain `start_with?` prefix comparison; set a global `Regexp.timeout`; cap `ignored_items` size.

**F11 — `DISABLE_DISCONNECT` is a UI-only control** (`sfind-4403814d008843fb82a05a9f8c38fa9f`, low; NEW / unverified). The flag meant to protect critical links is only returned to the UI to hide the button; `disconnect_interface` checks `system_set` and never reads it. Any `system_set` user drops a protected link through the API — command and telemetry cut for every operator on that interface. Recommendation (from the scan): load the `InterfaceModel` in `disconnect_interface` (and `connect_interface` with params) and refuse when `disable_disconnect` is set unless the caller is admin.

**F12 — Unauthenticated target/packet/item existence oracle** (`sfind-c29eb7f0461c412987ea3d5914a1a30b`, low; NEW / unverified). `tlm`, `set_tlm`, `get_item`, `get_tlm_values` and the `LATEST` paths resolve names via `TargetModel.packet_item` / `CvtModel.determine_latest_packet_for_item` before `authorize`; missing names return "does not exist", existing names return "Token is required". With no token and no visible rate limit on this path, an anonymous client on the network segment enumerates the mission's target, packet and item names — reconnaissance for the authenticated findings above. Recommendation (from the scan): perform the token/scope check before any lookup, or return a uniform not-found/unauthorized error.
